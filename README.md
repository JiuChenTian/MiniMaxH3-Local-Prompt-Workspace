# 镜序 H3 · 本地提示词工作台

面向 MiniMax H3 的中文提示词扩写软件。界面和数据运行在本机，由用户自己的语言/多模态模型识别素材并扩写提示词。此软件不包含 MiniMax 视频生成模型，也不直接生成视频。

## 启动

1. 使用 Node.js 22 或以上版本（当前开发电脑已有 Node.js 24）。无需安装 npm 依赖。
2. 双击 **启动工作台.bat**，保持启动窗口开启；程序就绪后自动打开 http://127.0.0.1:3210 。重复启动会打开已有工作台并保持控制台；关闭任一已连接控制台就停止工作台（复用窗口断开检测最多约 8 秒）。Windows 启动脚本采用 ASCII 内容及 CRLF 换行，避免中文编码与批处理解析问题。
3. 打开「模型与设置」，添加模型文件夹，每行一个绝对路径，点击「保存目录并扫描」。启动时也自动扫描已保存的目录。
4. 选择 GGUF 基础模型，需要多模态时选择配套 mmproj，填写 `llama-server.exe` 完整路径，然后「保存并启动模型」。
5. 模型加载完成后显示已连接。也可将服务地址设置为已经运行的本机 OpenAI 兼容服务，再点击「刷新连接」。

设置提供独立的 **llama-server 程序路径库** 和 **FFmpeg 程序路径库**，各可保存最多 20 个路径，每行一个。可以填写 `.exe` 文件或它所在的文件夹（也会检查 `bin` 子目录）。保存后识别为完整程序路径，通过「当前使用」下拉框切换版本；切换前先停止当前模型。路径检查只读，不会改动所指向的程序或模型目录。旧版本的单路径设置会自动显示在路径库中。

命令行启动：`npm start`。验证：`npm test`。启动后无需互联网。

## 推理引擎与模型

- 自行准备 [llama.cpp 官方发行版](https://github.com/ggml-org/llama.cpp/releases)、GGUF 权重与配套投影文件；本项目没有附带大型权重或推理二进制。
- 在设置中自动调用当前 llama-server 的设备列表，显示真实 GPU 型号与显存，不预填任何品牌或型号。可选自动、CPU 或指定 GPU；启动时再次验证所选设备。换电脑或引擎后点击重新识别，旧设备不存在时会报错，避免静默使用错误显卡。
- 自动读取 GGUF 元数据识别基础模型、视觉/音频投影，名称作为补充线索。同目录或名称相似的投影只给出候选建议，不擅自认定兼容。
- 递归扫描多个根目录，忽略符号链接防止循环；重叠目录去重。分片模型只允许选择第一片，其余分片需与第一片放在一起，完整性由 llama.cpp 加载时检查。
- `.safetensors` 和模型 `.bin` 文件可以发现，但不能通过本软件的 llama.cpp 启动器直接加载。GGUF 损坏或元数据超过保护上限时显示不可加载。
- 能力以运行中服务 `/props` 的 `modalities.vision/audio` 为依据。外部服务不提供该字段时，纯文本功能可用，多模态保守禁用；不会只根据模型名称假装支持。
- 启动/停止只管理本软件创建的模型进程。修改设置或切换模型前应先停止它。外部启动的服务不会被停止。

## 创作功能

- 5 种生成模式：T2VA（纯文字）、I2VA（一张首帧）、FL2VA（首帧与尾帧两张图，按添加顺序）、L2VA（一张尾帧）、REF2VA（至少一个参考素材，每个必须填写职责）。原来的电影叙事、分镜等保留为独立的写作侧重。支持快速 Prompt 与 H3 结构草稿；首尾帧模式自动使用 adaptive 比例。
- 接受剧情文本、镜头内容、故事大纲和已有提示词；可指定时长、比例、风格、补充约束、中英文输出。
- 剧情关联默认关闭：不会传入前情或历史。开启后传入手填前情与本次创作最近三轮结果；全局历史不会自动混入。新建创作清空关联，历史载入也从独立创作开始。
- 图片支持 JPG、PNG、WebP、BMP，需视觉模型；直接以图片消息发送。
- 视频支持 MP4、MOV、MKV、WebM、AVI，需视觉模型及 FFmpeg。从前 15 秒按 2.5 秒间隔采样，最多 6 张、最长边 768 像素。这是**视频画面抽帧分析**，不包含原声，也不能完整识别所有连续动作。短视频若未提取到帧会报错。
- 音频支持 MP3、WAV、FLAC，需音频模型；M4A、OGG、AAC 通过 FFmpeg 转成单声道 16 kHz WAV（最多前 120 秒）。直接发送的 WAV/MP3/FLAC 没有自动裁剪，应根据模型上下文选择短片段。
- 每个参考文件可填写职责。最多 9 个文件、单个 25 MB、合计 60 MB。这是本软件的处理限制，不代表 MiniMax 平台上限。
- 错误和不支持的素材明确提示，不会静默忽略。模型服务器仍可能因为具体格式、聊天模板或上下文限制拒绝请求，界面会展示错误。
- 提示词流式显示。「开始输出」与「提前终止」控制当前任务；终止后保留已输出文字，标记为部分内容，不作为完整历史记录保存。
- 中文与英文并排对照：默认生成后自动翻译，可关闭自动翻译或点击重新翻译；两栏均可编辑、单独复制，导出 TXT 包含两种语言。译文保留时间、结构字段和参考标签，引号中的对白/屏幕文字保持原语言。翻译也可提前终止。
- 「启动模型」加载已保存配置；「终止并卸载」会先取消输出，再释放本软件启动的模型。外部独立模型服务不被关闭。单次请求最长 10 分钟。
- Windows 双击启动使用内核 Job Object 管理工作台与模型进程。正常结束、Ctrl+C 或异常停止后，控制台仍保留；关闭窗口会终止所属服务及模型，不应把窗口关闭当成后台运行。浏览器单独打开，不加入模型的终止组。直接运行 server.mjs 仅供开发，不提供 Windows 控制台 Job Object 保证。

## 数据与隐私

仅监听 `127.0.0.1:3210`，模型服务地址仅允许本机 HTTP 地址；禁止重定向，跨站写入有来源检查。没有遥测、CDN 或云端模型调用。

设置保存在 `data/settings.json`，最近 100 条成功生成文本保存在 `data/history.json`；草稿保存在浏览器本地存储。图片/音频/视频不写入历史。媒体转换产生的系统临时目录在成功或失败后清理；异常断电可能留下临时目录。刷新页面后需重新添加媒体。关闭软件后可自行删除 `data` 和浏览器站点数据来清除记录。

## 写法依据

已实际逐项点击核对 [Prompt Builder 的五种模式](https://minimaxh3.studio/zh/guide/minimax-h3/prompt-builder)，按首帧、尾帧及参考生成分别构建写作指令。基础结构和 REF2VA 使用不同字段，参考素材按图片/视频/音频独立编号。

遵循用户指定的 [MiniMax H3 提示词指南](https://minimaxh3.studio/zh/guide/minimax-h3)：先确定工作流与镜头结构，再组织主体、动作、环境、美学、镜头和声音，并给每份参考素材分配明确职责。程序使用自己的编写指令，没有复制指南示例。网页描述的平台限制可能变化，软件中的时长/比例是写作参数，不保证目标平台接受。

本地推理协议参考 [llama.cpp 服务文档](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) 与 [多模态说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md)。

## 验证范围

自动化测试覆盖目录扫描与去重、GGUF 元数据/投影识别、无效文件、分片、剧情隔离、多模态能力限制、本地地址限制、程序多路径识别和启动复用，以及模拟本地服务的真实 HTTP 请求协议。

本机已使用用户提供的 Huihui-Qwen3-VL-8B Q4_K_M、配套 mmproj、llama.cpp b10588 及 FFmpeg 完成真实文字扩写、纯色图片识别和短视频抽帧识别测试。该服务报告不支持音频，工作台正确拒绝音频识别；音频格式转换另行通过。测试报告在 `data/local-smoke-report.json` 和 `data/live-model-report.json`。这些是兼容性冒烟测试，不代表复杂剧情或长视频识别质量已充分评估。用户提供的模型和工具目录只读使用，测试素材仅写入系统临时目录。

新增实测：RTX 5090 由当前引擎动态检测后选用；完成流式文字输出和中译英对照。`data/runtime-controls-report.json` 记录真实输出提前终止，以及强制结束独立控制台后工作台与真实 llama-server 同时退出的结果。
